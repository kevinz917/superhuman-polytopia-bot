# Ten-model parallel cohort setup

Cohort `mini-top10-20261030a` uses the frozen v4 authoring image
`im-MPssfTqJ9oBtnBMXIuA9Sm`, mini-SWE-agent 2.4.6, high reasoning and a
32,768-token response allowance. The model/provider manifest is
`configs/skirmish/mini-top10.json`. Public endpoint receipts and smoke results
are saved beside this document.

The initial dispatch allocates all 20 model × track cells concurrently. Match
workers allow 32 concurrent games. Each track has its own shared-map round robin
against the other frozen bots and the fixed expert. Failed submissions stay in
the report but have no invented Elo. Engine/referee caps stay unresolved.

All authoring and games run on Modal staging. Coding sandboxes have two CPU
cores, 2 GiB RAM, no network, the real engine CLI and nine public test maps. No
opponent or checkpoint is supplied. Sources, Wasm, complete trajectories,
feedback and private referee logs remain in Modal volume `polytopia-skirmish`.
Only compact reports are exported locally.

```sh
modal run --env staging experiments/modal_skirmish.py::mini_cohort_probes --prefix <fresh-prefix>
modal run --env staging --detach experiments/modal_skirmish.py::mini_cohort_start --prefix <fresh-prefix>
modal run --env staging experiments/modal_skirmish_report.py --prefix <fresh-prefix> --output /tmp/cohort.json
python3 scripts/render_skirmish_cohort.py /tmp/cohort.json /tmp/cohort.md
```

Ten smoke tests each exercise two actual upstream-agent stages: bash execution,
early submission and history resume. All ten passed; saved completed-call cost
was $0.044664. The shared CLI/referee suite passed 38 tests, and the live offline
sandbox preflight passed before authoring began.

Two administrative cases are explicitly distinguished from bot performance:

- A redelivered Sol authoring dispatch was rejected before overwriting its run.
  The original worker did not reach source freeze and left a stale status.
  That interrupted attempt is excluded and replaced with a fresh full-budget run.
  Tournament workers use a distributed per-game claim so redelivered inputs
  return one canonical committed game rather than adding another game.
- DeepSeek Pro's original one-shot worker aborted because OpenRouter returned
  `usage.cost=0` and upstream strict accounting rejects non-positive cost.
  That attempt is invalid and excluded. A fresh full-budget replacement uses
  the supported `MSWEA_COST_TRACKING=ignore_errors` setting. A subprocess probe
  verified that zero-cost responses retain their tool action and are counted
  as zero instead of aborting. The prompt, API parameters, provider, coding
  image and bot runtime are unchanged. The replacement ledger is archived in
  `mini-cohorts/<prefix>/replacements.json` and exported in the compact report.

The one-shot and feedback tracks must not be mixed into one Elo ranking. One
valid authoring attempt per model/track and one hidden map per family make this
a lightweight pilot. It is not a statistically reliable ranking of models.

Sol's valid replacement submitted 232,833 bytes of Rust source (including copied
public engine modules). An undeclared 200,000-byte authoring cap blocked source
freeze. This cap was removed. The exact deterministic source-writing operations
were replayed twice in the original immutable SDK image; both produced SHA-256
`48f9240dcc2418a9aad7078c3dd1c02ae5d4b457f22e76fe6619d808d1763cff` and
6,425 lines, matching its final recorded `wc -l`. No extra model call, edit, or
agent feedback was added. The reconstructed source was independently compiled
and evaluated under the original game limits. The recovery receipt is adjacent.

Following the user's instruction, billing metadata is now strictly optional
bookkeeping: it cannot reject a model response or stop the harness. Five added
upstream-response tests cover zero, absent, null and malformed metadata. The
updated suite passed 43 tests, with one operator-only rule-book test skipped.
