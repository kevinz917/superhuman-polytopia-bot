# lookout: a hybrid transformer trunk, from scratch on Daytona (2026-11-01)

The parallel arm to farsight (Curio: conv trunk + global pooling bias + observation history, from scratch). Same
game, same PPO recipe, same observation version (3, opponent history), same parameter budget; only the trunk
differs. If farsight gains from the pooling bias, lookout says whether full attention buys more; if both are flat,
global context was not the lever.

Branch `claude/lookout` = `claude/obs-v3-history-03c82d` (farsight's code) + `claude/daytona-hero` (the Daytona
harness) + this. The farsight worktree and the Curio head's published code are never touched from here: the Curio
head is only read (`scp` of farsight's `latest.npz` for the ladder).

## The network (`network.init attention`)

`trunk` unchanged up to the tiles: stem, `blocks` residual conv blocks (normalized-v2: LayerNorm + SiLU), optional
extra blocks. Then, when the checkpoint has attention blocks:

```
x = tiles + pos[:n]                                   # learned positional embedding, one row per tile
for block in attention:                               # pre-LayerNorm transformer blocks
    x = x + proj(MHSA(norm1(x)))                      # 4 heads of 32 dims at width 128, fp32 softmax
    x = x + mlp_out(silu(mlp_in(norm2(x))))           # 4x MLP
tiles = attention_norm(x)
```

The heads are the normalized-v2 heads (mean/max pooling + global vector, family / source / target, critic hidden):
nothing after the tiles changes, so the learner, the actors' inference server, the arenas, search and Studio all
load a lookout checkpoint through `network_spec` (`attention` in the checkpoint json) and `_template_params`.

Matmuls follow the conv torso's precision policy (`TRUNK_DTYPE` bf16 operands on the learner and the inference
server, fp32 results, `PRECISION` for the einsums); the residual branches start at GPT-2's 1/sqrt(2 x depth) scale
so the residual stream keeps the convolutional features' scale at init.

**Size.** 2 conv blocks + 3 attention blocks at width 128:

| | hero (4x128) | lookout (2x128 + 3 attention) |
|---|---|---|
| parameters (obs v3) | printed by `tests/test_attention_trunk.py::test_lookout_matches_hero_parameter_count` | within 15% |
| trunk FLOPs per position (14x14) | ~0.46 GFLOP (8 convs) | ~0.55 GFLOP (4 convs + 3 blocks of ~97 MFLOP) |

A 196-token sequence is small for attention: one block costs about one 3x3 conv block, so the arm is FLOP- and
parameter-matched rather than bigger.

## Learner cost and the attention kernel (smoke + Modal H100 bench, 2026-11-01)

The smoke on 4x RTX PRO 6000 trained at 6.9 s per 262k batch (the conv hero: 1.86 s), a ~38k samples/s cap, with
the actors at 12-14k samples/s per PRO 6000 box (conv hero: 29.5k). The first learner OOMed a 96 GB GPU on one
61.6 GiB allocation: the XLA attention keeps [rows, heads, 196, 196] scores and softmax per minibatch row.
`experiments/modal_attention_bench.py` (policy trunk, 4096-row device minibatch, forward + backward, H100):

| kernel | remat | step ms | note |
|---|---|---|---|
| einsum (XLA, fp32 softmax) | on | 118 | the smoke's kernel; without remat: OOM (34.7 GiB on 80 GB) |
| `jax.nn.dot_product_attention`, automatic | off | 86 | fell back to XLA's unfused kernel |
| `dot_product_attention(implementation='cudnn')` | off | **56** | value max abs diff 2e-4 on a 0.15 scale (bf16 q/k/v) |
| cudnn, head dim 64 (2 heads) | off | 52 | not worth an architecture change |
| conv-only parts of the same trunk | | 32 | 2 conv blocks + 3 MLPs |

So the fused kernel is the lever (2.1x on the attention-heavy step); the remaining gap to the conv hero is the
attention itself at 196 tokens x 4 heads of 32 (~8 ms per block, forward + backward, 4096 rows). `network`
defaults (`POLYTOPIA_ATTENTION_IMPL=auto`): cuDNN SDPA on a GPU backend (learner and inference servers share it),
fp32 einsum on CPU (arenas, Policy wrapper); remat only with einsum. The run was restarted on it at update ~50.

## The run (`experiments/hero/lookout-1v1.json`, plan `lookout-1v1`)

farsight's game and PPO settings (`experiments/curio/configs/hero-1v1-scratch.json`): real 2.17.3 rules, obs v3,
no peace, a capped game is a loss for both seats, omniscient critic, gamma .995 / turn clock .99, batch 262k,
minibatch 16k, 1 epoch, LR 3e-4 -> 1e-4 over the last 25%, checkpoint every 20 updates. Differences:

- `lr_warmup_updates` 200 (new `LearnerConfig` knob, `warmed_learning_rate`): a from-scratch attention trunk under
  PPO with a fresh critic is the one place a warmup is cheap insurance.
- platform knobs are main's Daytona set (`send_thread` off; `stream_views` on, no coded views / value devices /
  GPU lock, which are Curio's 4090 workarounds).
- `seed` 811.

Topology (docs/hero-daytona-2026-10-28.md option B): 4x RTX PRO 6000 spot learner, 5 PRO 6000 GPU-inference actor
sandboxes (48 processes each, bf16 server), ~$30/h, ~110-125k samples/s for the conv hero; lookout's actor rate is
measured by the smoke.

From scratch on the harness: the plan has `scratch` instead of a resume point. `hero.py launch` writes a random
init on the hub (`node.py hero_random_parent`, obs v3, `attention` 3) to `/vol/parents/<run>/random-init.npz`,
the learner starts from it until the run folder has `latest.npz` (`fallback_parent`), and there is no `start`
ladder reference.

## Comparing with farsight

`python experiments/daytona/hero.py sync-farsight` copies the Curio head's `runs/farsight/latest.{npz,json}`
(read-only ssh) to the volume as `/results/distributed/ladder/farsight-latest.npz` plus a stage-tagged copy, and
logs the stage to `runs/hero-daytona/farsight-sync.jsonl`. The ladder's `farsight` reference points at that file;
rounds before the first sync skip it. Each 2-h round: lookout's latest vs hero1, champion, c3 and farsight on 32
proposed-v1 maps x 2 seats, deterministic, in 4-vCPU CPU sandboxes. Read the farsight column together with the
sync log: the reference is whichever farsight checkpoint was synced last, and the two runs train at different
rates (Curio measured ~77k samples/s for the conv hero, Daytona's 4x PRO 6000 topology ~110-125k/s; both to be
re-measured on these networks), so compare at matched samples (training.jsonl of both) as well as at matched wall
clock.

## Runbook

```bash
cd .claude/worktrees/lookout
python experiments/daytona/hero.py hub --ttl-hours 48
python experiments/daytona/hero.py publish

python experiments/daytona/hero.py keep smoke-lookout-1v1 --no-eval --once
python experiments/daytona/hero.py launch lookout-1v1 --hours 24

python experiments/daytona/hero.py sync-farsight                                # every few hours
python experiments/daytona/hero.py status lookout-1v1
```

## Close-out (2026-11-02 09:33 CST)

Stopped by the user's decision (one-variable cap-rule restarts take the Daytona slot) at **update 13931, 3.65 B
samples, 19.3 h of training**, ~$665 of Daytona credits (learner + 5 actors ~$30/h, evals and two actor replacements
on top). `final.npz`, `latest.npz`, 220 snapshot files, `training.jsonl` and the eval history are on the volume under
`/results/distributed/lookout-1v1/`; the learner and actor sandboxes are deleted; no final ladder was run (it can be
run later from `final.npz` with `hero.py eval lookout-1v1 --final`).

Verdict: at equal samples the attention trunk trails the repaired pooling conv trunk (0.31-0.32 head-to-head at
2.4-2.6 B) and costs 5.8x per learner step before kernel work, ~2.7x after; it beat only the original, broken
farsight. Working learner settings for an attention trunk on 4x RTX PRO 6000, should one be trained again: cuDNN
SDPA (`POLYTOPIA_ATTENTION_IMPL=auto`), no remat, `stream_views` off, `serialize_gpu` on, `value_sub` 2048 with
`value_sub_two_seats`, LR warmup 200 updates.
